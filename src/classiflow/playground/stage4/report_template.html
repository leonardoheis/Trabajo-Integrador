Human review — from the user's side, today

There is currently no dedicated review screen in this codebase. Reaching a "reviewer" experience today means calling the classification API directly.

1

Pull the queue

GET /classification/review-queue returns every document at review_route = human_review — job id, guessed label, and the smells that triggered the flag.

2

Look at the file

The reviewer opens the PDF from its stored_path under storage/documents/review/human_review/ and reads it directly — no in-app viewer yet.

3

Submit the correct label

POST /classification/{job_id}/decision with the corrected label and an optional notes string.

4

The system finalizes it

The record flips to accept, human_overridden = True, and RoutingNode moves the file into classified/<label>/.

No frontend exists for this yet. Every step above is an API call — today's "reviewer" is whoever calls these two endpoints directly.
